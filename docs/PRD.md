# yuno-webdesign 製品要求設計書（PRD）

- 作成日: 2026-08-22
- 対象: yuno-webdesign コーポレートサイト（実案件・自社サービス）
- 想定読者: 開発者本人（設計整理用）／将来のチームメンバー
- ステータス: ドラフト（Q&Aベースで継続更新）

## 1. 背景・概要

yuno-webdesign は、個人事業主・小さな会社向けにホームページ制作を行う事業のコーポレート
サイトである。丁寧なヒアリングと「伝わるデザイン」を強みとし、サイト自体もそのブランド
体験のショーケースを兼ねる。

現状の構成（維持する）:

| ページ | ファイル | 役割 |
|---|---|---|
| トップ | `index.html` | Hero / Works / About / Activity / Service / Guide 導線 / News / 問い合わせ（フッター内簡易フォーム） |
| お問い合わせ | `contact.html` | 本フォーム（お名前・メール・会社名・相談カテゴリ・内容） |
| よくある質問 | `faq.html` | FAQ 一覧 |
| ご相談の流れ | `guide.html` | 相談〜納品までのフロー説明 |

フォーム送信は `send-contact.php` が受け、`mb_send_mail()` で運営者宛てにメール転送する
（AJAX 送信、`js/main.js` の `initContactForm`）。

## 2. 目的・ゴール

以下 3 つを同格の最重要ゴールとする（優先順位付けはしない）。

1. **問い合わせ・受注の獲得** — 個人事業主／小さな会社からの制作依頼の問い合わせ数を増やす
2. **実績・信頼性のアピール** — ポートフォリオとしての説得力を高め、信頼を得る
3. **ブランディング・世界観の発信** — yuno-webdesign らしさ（デザイン哲学・雰囲気）を伝える

> 現時点では定量 KPI（問い合わせ件数の目標値など）は未設定。今後の検討課題とする。

## 3. スコープ

- サイト全体（`index.html` / `contact.html` / `faq.html` / `guide.html`）の要求整理
- ページ構成の新規追加・削除は今回のスコープ外（現状 4 ページ構成を前提とする）
- 重点的に言語化する領域: **機能要件 / 非機能要件 / 運用・保守要件**
  （デザイン・UX ガイドラインは今回は優先度を下げる）

## 4. 想定ユーザー

- **サイト訪問者**: ホームページ制作を検討している個人事業主・小さな会社の経営者
- **PRD の読者**: 開発者本人、および将来ジョインする可能性のあるチームメンバー

## 5. 機能要件

### 5.1 現状維持する機能（既存実装のベースライン）

- ヘッダー: ロゴ／グローバルナビ（SP はハンバーガー開閉）／お問い合わせ CTA
- スクロールでヘッダーに影を付与（`initHeaderScrollShadow`）
- フィックスボタン（`initFixedButton`）
- スクロールリベアルアニメーション（`initScrollReveal`、非対応ブラウザは即表示フォールバック）
- Service セクションのパララックス演出（`initServiceParallax`）
- フッター内簡易お問い合わせフォーム（`index.html`）＋ `contact.html` の本フォーム
  - 項目: お名前 / メールアドレス（`_replyto`）/ 会社名・事業名（任意）/ 相談カテゴリ / 相談内容
  - AJAX 送信 → `send-contact.php` → 運営者宛てメール転送、成否をフォーム上に表示
- FAQ ページ、ご相談の流れ（Guide）ページ

### 5.2 追加要件（お問い合わせフォーム）

現状のフォームはバリデーション（必須項目・メール形式）とメール転送のみに対応。以下を
追加要件とする。

| # | 要件 | 内容 |
|---|---|---|
| F-1 | スパム対策 | reCAPTCHA 等のボット対策を導入し、無効な送信を抑制する |
| F-2 | 自動返信メール | 送信者（`_replyto`）宛てに受付完了通知メールを自動送信する |
| F-3 | 送信内容の保存 | 送信内容を DB または CSV 等に保存し、メール消失時にも履歴を追跡できるようにする |

> 送信内容を保存する場合、個人情報（氏名・メールアドレス）を扱うため、保存先のアクセス
> 制御・保持期間・削除方針は今後の検討課題とする。

## 6. 非機能要件

優先的に基準を定める領域として **パフォーマンス** と **SEO** を挙げる。

| 領域 | 要件（ドラフト） |
|---|---|
| パフォーマンス | 表示速度・PageSpeed 系の指標を改善対象とする。具体的な目標数値（例: PageSpeed スコア、LCP/CLS 等の Core Web Vitals 目標値）は今後決定 |
| SEO | タイトル・meta・構造化データ等の検索流入改善方針を今後具体化する（`index.html` には既に `meta description` あり） |
| アクセシビリティ | 今回は優先度を下げるが、既存実装は `aria-expanded` / `aria-controls` / `u-sr-only` 等に一部配慮済み |
| ブラウザ・デバイス対応 | 今回は優先度を下げるが、既存実装はレスポンシブ（`u-pc-only` 等）およびアニメーション非対応ブラウザへのフォールバックを持つ |

## 7. 運用・保守要件

- 制作・更新・保守はすべて **開発者本人が単独で** 行う体制
- CMS 等クライアント側での更新は想定しない（コード直接編集で対応）
- フォーム関連の追加要件（5.2）に伴い、送信データの保存・自動返信のテンプレート管理など、
  運用フローに組み込むべき保守作業が増える点に留意する

## 8. 制約条件

- **ホスティング**: PHP の `mail()` 関数（実装上は `mb_send_mail()`）が利用できるレンタル
  サーバーを前提とする
- **技術スタック**: 静的 HTML + SCSS（`scss/` → コンパイル）+ Vanilla JS（`js/main.js`）+
  PHP（フォーム送信処理のみ）
- 将来的に Vercel / Netlify 等の静的ホスティングへ移行する可能性は本 PRD 時点では想定しない
  （移行する場合、PHP 依存のフォーム送信処理は代替手段への置き換えが必要になる点に留意）

## 9. スケジュール

- 公開・納品の目標時期: **未定**（本 PRD 内では期限を設けず、内容の整理を優先する）

## 10. 未決事項・今後の検討課題

- 定量 KPI（問い合わせ件数目標など）の設定
- パフォーマンス・SEO の具体的な数値目標
- フォーム送信データの保存方式（DB / CSV）とその保持期間・アクセス制御
- reCAPTCHA 等スパム対策の具体的な導入方式
- 自動返信メールの文面・テンプレート
